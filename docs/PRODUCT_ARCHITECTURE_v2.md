**文件名：** PRODUCT_ARCHITECTURE_v2.md  
**版本：** 2.1.0

**产品定位：** 帮助人理解自己、理解彼此、梳理关系事件并逐步改善相处方式的私密研究原型。

## 1. 产品改版目标

### 1.1 核心定位

本轮改版不是简单的视觉换肤，而是从产品认知、信息架构、交互方式和用户语言四个方面进行体验重构。

| 第一版 | 第二版 |
|---|---|
| 关系分析工具 | 理解自己与他人的陪伴空间 |
| 功能入口平铺 | 按自然认知顺序引导 |
| 数据与状态展示 | 叙述式体验 |
| 分析和测评感 | 理解与探索感 |
| 操作导向 | 用户感受导向 |

产品不得提供人格诊断、道德评分、关系匹配率或关系预测。

### 1.2 六个导航入口与五段认知动线

产品采用六个一级导航入口：

1. 首页
2. 认识自己
3. 理解彼此
4. 面对一件事
5. 一起改善
6. 回顾成长

首页承担全局入口和进度续接功能，其余五项构成认知体验主线。

五段认知动线：

- 认识自己：了解自己的感受、需求、习惯和相处方式。
- 理解彼此：探索不同视角，不预设双方必然一致。
- 面对一件事：从具体事件出发，区分事实、解释、感受和需求。
- 一起改善：在自愿、安全的前提下形成可执行的相处约定。
- 回顾成长：回看约定执行情况，记录变化，并自主决定是否更新个人档案。

并非所有用户都必须完成全部阶段。用户可以跳过非必要体验，但不能绕过安全检查、必要授权和关键数据确认。

## 4. 核心业务模块

### 4.1 个人档案

目标：帮助用户逐步了解自己的相处习惯。

设计要求：

1. 一次只呈现一个主要问题。
2. 支持跳过、保存和修改。
3. 支持随时退出。
4. 不把用户回答转化为人格裁定。
5. 不输出道德评分。
6. 默认保持私密。
7. 未经用户主动授权，不得向另一方共享。
8. 档案回写必须经过用户主动确认。

### 4.2 关系差异地图

必须区分单人模式和双方模式。

**单人模式：**

- 只展示用户自己的观察。
- 展示用户认为可能存在的共同点。
- 展示用户感受到的差异。
- 展示尚未验证的问题。
- 不得将个人推测包装成双方共同结论。
- 不得声称已经了解另一方的真实想法。

**双方模式：**

- 双方分别完成独立输入。
- 双方分别明确授权本次关系探索。
- 仅比较双方明确授权的数据。
- 不得默认开放完整个人档案。
- 任意一方撤回授权后，相关共享内容立即失效。
- 不得将一方的输入推断成另一方的真实想法。

### 4.3 事件梳理

事件模块是产品核心业务流程。

业务步骤：

1. 开始前的知情说明与安全关怀。
2. 用户私密叙述。
3. 事实整理。
4. 不同解释。
5. 感受整理。
6. 需求整理。
7. 本人确认。
8. 可选方向。
9. 生成三份整理结果。

设计要求：

- 原始用户输入必须保留。
- 加工内容必须能够追溯到原始输入。
- 不得将系统推断当成事实。
- 用户可以返回修改自己的内容。
- 用户可以跳过非必要步骤。
- 不得强迫用户进入共同协商。
- 必须遵循 SAFETY 安全状态机及路由限制。

### 4.4 三份整理结果

三份整理结果不是测评结论，而是帮助用户重新理解事件的材料。

| 整理结果 | 内容 |
|---|---|
| 事实与经过 | 用户描述的事件、时间及可确认事实 |
| 不同理解 | 不同解释、待验证假设、感受与需求 |
| 可选方向 | 用户可以考虑的行动及需要进一步确认的问题 |

所有推断必须明确标记为「待验证假设」。

不得把解释当成事实，也不能替用户判断另一方的真实意图。

### 4.5 一起改善：共同约定

共同约定必须满足：

1. 用户主动选择建立约定。
2. 双方分别明确同意。
3. 不得以沉默视为同意。
4. 不得以系统建议代替双方决定。
5. 任意一方可以退出。
6. 任意一方可以撤回尚未完成的授权。
7. 不得强迫用户接受或继续执行约定。

每份约定包含：

- 想改善的具体事情。
- 双方各自认可的行动。
- 双方各自愿意尝试的内容。
- 适当的回顾时间。
- 修改约定的方式。
- 结束约定的方式。

### 4.6 回顾成长

复盘内容：

1. 当初希望改善什么。
2. 实际发生了什么。
3. 哪些事情有所变化。
4. 哪些地方仍然困难。
5. 自己有哪些新的认识。
6. 是否愿意更新个人档案。

设计要求：

- 不将复盘结果作为关系评分。
- 不评价用户是否做得足够好。
- 支持修改和删除复盘内容。
- 档案回写必须经过用户主动确认。
- 不得将复盘内容自动共享给另一方。


## 5. 事件状态机

### 5.1 事件状态定义（严格对齐第一版源码 WorkflowStatus 八态）

| 状态 | 说明 | 后续 |
|---|---|---|
| CONSENT | 知情同意 | 安全检查 |
| SAFETY_CHECK | 安全检查 | 继续或安全出口 |
| PRIVATE_INTAKE | 私密叙述 | 事实整理 |
| FACT_MAP | 事实整理 | 不同理解 |
| HYPOTHESES | 不同理解（假设整理） | 本人确认 |
| INDIVIDUAL_CONFIRMATION | 本人确认 | 可选方向 |
| OPTIONS | 可选方向 | 生成三份整理结果 |
| SAFETY_SUPPORT | 安全支持出口 | 停留支持，不得推进共同协商 |

以上八态名称与 `eventMachine.ts`、`domain.ts` 的 WorkflowStatus 完全一致，仅作程序内部使用，不得直接展示给用户。

### 5.2 一版八态基线

事件核心流程按源码原始顺序流转：

CONSENT → SAFETY_CHECK → PRIVATE_INTAKE → FACT_MAP → HYPOTHESES → INDIVIDUAL_CONFIRMATION → OPTIONS

SAFETY_SUPPORT 为安全出口状态：不安全、不确定或拒绝回答时进入，绝不作为正常推进路径。本修订不新增、不删除、不合并任何既有状态。

### 5.3 FEELINGS_NEEDS 归属说明

FEELINGS_NEEDS 不是 WorkflowStatus，不是独立状态。它是一版源码中的用户输入数据字段归属，表示"感受与需求"数据，挂接在事件流程各阶段的数据结构中，参与内容整理与来源关联，不参与状态转换。不得将其虚构为状态机节点。

### 5.4 转换条件

| 从 | 到 | 转换条件 |
|---|---|---|
| CONSENT | SAFETY_CHECK | 用户完成知情同意并开始 |
| SAFETY_CHECK | PRIVATE_INTAKE | 安全状态为 clear 且用户选择继续 |
| SAFETY_CHECK | SAFETY_SUPPORT | 用户有担忧、不确定或不想回答 |
| SAFETY_SUPPORT | 仅停留 | 提供支持，不自动推进；不得进入共同协商流程 |
| PRIVATE_INTAKE | FACT_MAP | 用户提交私密叙述 |
| FACT_MAP | HYPOTHESES | 用户完成事实整理 |
| HYPOTHESES | INDIVIDUAL_CONFIRMATION | 用户完成不同理解整理 |
| INDIVIDUAL_CONFIRMATION | OPTIONS | 用户确认内容无误 |
| INDIVIDUAL_CONFIRMATION | 返回前序状态 | 用户要求修改 |
| OPTIONS | 产出节点 | 生成三份整理结果 |

任意状态均允许用户退出、保存后离开；保存恢复必须经过统一状态转换入口，不允许绕过状态校验。

### 5.5 保存恢复与异常处理

1. 合法状态下随时保存。
2. 恢复时校验当前状态与目标页面是否匹配。
3. 状态不一致时提示用户选择继续或重新开始。
4. 异常中断不得造成数据丢失。
5. 恢复后安全检查中用户有担忧，重新进入 SAFETY_SUPPORT。


## 6. 路由守卫、数据关联与删除

### 6.1 路由守卫

1. 未开始安全确认前，不得进入事件梳理流程。
2. 安全状态不是 clear 时，不得进入共同协商流程。
3. 用户有担忧、不确定或不想回答时，必须停留在 SAFETY_SUPPORT，不得跳过。
4. SAFETY_SUPPORT 不得返回共同协商流程。
5. 未完成本人确认前，不得生成三份整理结果。
6. 未获得双方明确授权前，不得展示双方比较内容。
7. 任意页面刷新、返回或恢复，均须重新校验路由许可。

### 6.2 数据关联规则

事件、整理结果、约定、复盘、档案之间的关联关系：

| 数据 | 关联内容 |
|---|---|
| 事件 | 叙述、事实、解释、感受与需求、整理结果 |
| 整理结果 | 对应事件的三份材料 |
| 约定 | 对应事件、双方同意记录、回顾时间 |
| 复盘 | 对应约定或事件、成长记录 |
| 档案 | 个人输入、回写来源 |

所有关联均记录来源标识，任何加工内容可追溯到原始输入。

### 6.3 删除策略

1. 删除事件时，级联删除其整理结果；保留已形成的约定时应提示用户关联将解除。
2. 删除约定时，解除与事件、复盘的关联；双方同意记录按隐私规则处理。
3. 删除复盘时，解除与事件、约定的关联，可选择是否保留成长记录。
4. 删除个人档案时，解除全部共享授权，共享数据立即失效。
5. 撤回共享授权时，共享数据立即失效，但本地数据保留。
6. 清除事件记录必须经过用户明确确认。
7. 删除操作的确认、执行与结果提示均需完整记录。


## 7. 隐私承诺边界

1. 所有个人输入默认私密保存，不公开。
2. 未经用户明确授权，不得向另一方共享任何内容。
3. 授权可随时撤回，撤回后共享数据立即失效。
4. 不收集与产品功能无关的个人信息。
5. 隐私说明与数据管理置于辅助入口，说明保存、共享、撤回与删除方式。
6. 删除个人档案前必须明确确认，并提供删除后果说明。
7. 产品内不提供、不编造任何热线号码；涉及安全支持时仅引导用户自行联系当地可信资源。
8. 分析、整理结果不用于任何评分、排名或第三方使用。

| SAFETY_SUPPORT 出口 | 不得返回共同协商流程 |

| 热线号码 | 不编造，不内置虚构号码 |
| 清除事件记录 | 必须经过用户明确确认 |

### 8.2 改版前后行为对照

| 事项 | 第一版 | v2 修订版 |

## 8.5 双方授权与隐私机制（独立章节）

### 8.5.1 授权模型

1. 双方分别完成各自的独立输入。
2. 双方分别明确授权本次关系探索的共享范围。
3. 授权按数据项粒度进行，不默认开放完整个人档案。
4. 授权记录保存：授权人、授权时间、授权范围、失效条件。

### 8.5.2 授权撤回

1. 任意一方可随时撤回已授予的共享授权。
2. 撤回后，与该授权相关的共享数据立即失效，不得继续展示给另一方。
3. 撤回不删除本地数据，仅停止共享。
4. 撤回操作须有明确确认和撤销说明。

### 8.5.3 单方退出

1. 任意一方可随时退出共同流程（事件、约定、探索）。
2. 退出后，对方不得继续查看退出方的数据。
3. 退出后已形成的内容按删除策略处理或封存，须有明确说明。

### 8.5.4 共享数据失效处理

1. 授权到期、撤回或退出时，共享视图立即刷新为不可见。
2. 缓存中不得残留已失效的共享内容。
3. 失效处理后，页面展示状态须与实际授权一致。

## 9. 首页续接机制

1. 首页根据保存状态展示「接着上次」入口。
2. 续接记录包含：上次所在状态、事件标识、时间。
3. 点击续接时校验当前状态与目标页面匹配，不匹配则提示继续或重新开始。
4. 无续接记录时不做虚假提示。
5. 续接后安全检查有担忧时，重新进入 SAFETY_SUPPORT。

## 10. 空状态与路由异常

1. /event 无进行中事件时，展示空状态引导：开始一次梳理。
2. /report 无整理结果时，展示空状态引导：先完成一次事件梳理。
3. 空状态页面提供明确的返回入口，不展示空白页。
4. 无效或越权路由，统一跳转到首页并提示原因。
5. 任何异常路由不得绕过状态校验。

## 11. 设计与交互原则

1. 视觉方向：温暖、克制、留白，减少测评感。
2. 交互原则：一次一问、可跳过、随时保存、随时退出。
3. 文案替换表：页面文案用用户可理解语言（如「写下经过」「理清事实」），状态机名称仅内部使用。
4. 系统推断一律标记「待验证假设」。
5. 不得使用诊断、评分类表述。

## 12. 技术架构约束

1. 前端：React + TypeScript，与现有代码库保持一致。
2. 数据存储：localStorage 为主，迁移版本号管理。
3. 所有状态转换经过统一转换入口，保证幂等。
4. 数据结构升级时提供迁移，不丢失用户数据。
5. 生产构建与线上版本分离，未经批准不覆盖 Cloudflare 线上版本。

| 双方关系模式 | 双方独立授权；任何一方撤回后，共享数据立即失效 |
| SAFETY 安全机制 | 严格遵循第一版八态状态机，不擅自改变安全判断规则 |
| 安全路由 | 不安全、不确定或拒绝回答时，不得进入共同协商流程 |
| 事件状态机 | 所有状态转换经过统一转换入口，不允许绕过状态校验 |
| FEELINGS_NEEDS | 作为事件数据字段归属，不虚构为独立状态 |
| 数据保存 | 支持合法状态下保存、恢复及异常处理 |
| 数据删除 | 明确处理事件、整理结果、约定、复盘和档案之间的关联 |
| 档案回写 | 必须由用户主动确认 |
| 个人隐私 | 未经授权不得共享个人档案 |
| 用户体验 | 不输出人格诊断、道德评分和关系匹配率 |
