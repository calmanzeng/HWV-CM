# HWV-CM 产品架构与原型说明

**版本：** 0.2 · 原型复审修订稿  
**依据：** `docs/HWV-CM_1.0_研究与产品规格书.md`、`model/HWV-CM_1.0.json`、`docs/ROADMAP.md`、研究阶段交付  
**定位：** 本地优先的认知整理与沟通反思研究原型；不是心理测验、诊断工具、三观打分器或关系匹配工具。

## 1. 产品决策摘要

1. 使用场景入口不设档案完成门槛：用户可以直接处理一次事件，也可以先整理个人档案或关系认知。
2. 将“观察记录”和“由记录支持的解释”分开保存；事件中的事实、争议、解释、感受、需求、请求分别作为不同 claim 类型。
3. 本地版本不调用云端推理服务，不上传叙述。事件整理结果只采用用户确认的数据与透明模板；系统不凭单段叙述“读心”。
4. 单人模式只总结当前用户自己的叙述。缺席方的动机、人格和价值一律显示“未知／有待核实”。
5. 高风险筛查优先于共同分析；触发后旁路共同调解、假设生成和约定流程，提供安全支持出口。
6. 双人共享在当前单人研究原型中暂未开放。只有完成双方身份核验、逐项授权、加密分享包、密钥分渠道交接和接收预览后，才可进入双人试点；任何本地撤回都不能删除接收方已导出的副本。
7. `localStorage` 表示“不向服务端发送”，不等于加密保险箱。共享设备、浏览器扩展、恶意脚本或系统账户访问仍可能读取本机数据；必须清楚提示并提供清除入口。

## 2. 信息架构与导航

全局侧栏/顶部导航保持六个一级工作区：

| 工作区 | 用户任务 | 主要对象 |
|---|---|---|
| 首页 | 选择场景、查看本机数据说明与最近事项（产品版） | 汇总 |
| 个人档案 | 访谈、价值优先排序、自由记录、检视 58 个候选构念 | person / claim |
| 关系 | 查看关系差异地图示意；双人共享入口暂未开放 | relationship（后续） |
| 事件分析 | 单人自愿输入、事实映射、假设确认与整理结果 | event / claim / option |
| 约定与复盘 | 跟踪承诺、确认复盘、选择是否回写档案 | agreement / follow-up |
| 关于与数据 | 模型来源、证据登记、原型声明、导出／导入／删除 | provenance / local data |

产品入口之间可以互相跳转。个人档案为空时显示“目前还没有足够资料”，不以默认值填满构念，也不阻止事件分析。全站固定显示统一研究原型声明；原型页面另标明“静态交互稿，不保存真实数据”，不能把示意链接描述成已保存、已导出或已删除。数据管理和删除入口在导航与关于页均可到达。

## 3. 路由与关键屏幕

原型文件位于 `design/hwv-cm-prototype/`，屏幕和建议路由如下：

| 原型屏 | 建议路由 | 评审重点 |
|---|---|---|
| `home.html` | `/` | 使命、研究声明、三个入口、私密状态 |
| `profile.html` | `/profile` | 访谈进度、19 项相对排序、58 构念的数据质量与未知态 |
| `relationship.html` | `/relationships/:id` | 差异地图示意；显示双人共享暂未开放与身份/加密边界 |
| `event-consent.html` | `/events/new/consent` | 单人用途说明与明确同意；双人模式暂未开放 |
| `event-safety-check.html` | `/events/new/safety-check` | 私密自评守卫；担心或不确定时只进入安全支持 |
| `event.html` | `/events/new/intake` | 单人私密叙述，结构化事实/解释/感受/需求 |
| `event-map.html` | `/events/:id/confirm` | 事实地图、待验证问题、逐项确认锁；未确认不能进入整理结果 |
| `report.html` | `/events/:id/results` | 分歧地图、个人沟通建议、协商选项三份整理结果 |
| `safety.html` | `/events/:id/safety` | 旁路调解、安全退出、现实支持建议 |
| `follow-up.html` | `/agreements` | 未来功能示意；当前单人原型不开放共同约定，仅展示复盘/回写交互 |
| `about.html` | `/about` | 模型证据、免责声明、数据导入导出与清除 |

主要链路：`首页 → CONSENT → SAFETY_CHECK → PRIVATE_INTAKE → FACT_MAP → HYPOTHESES → INDIVIDUAL_CONFIRMATION → OPTIONS → MUTUAL_AGREEMENT → FOLLOW_UP`。其中同意与安全筛查是独立页面和真实状态守卫；高风险或不确定只进入 `SAFETY_SUPPORT`。当前版本仅开放单人路径，关系共享和共同约定视图先标为未开放。

## 4. 前端架构

```text
页面与组件
  ├─ 场景导航、表单、清单、整理结果、同意确认
  ├─ 只读原型声明与安全提示
  ↓
领域服务（纯函数优先）
  ├─ event state machine：守卫状态跳转、禁止越级
  ├─ claims：类型校验、来源/所有者/确认状态
  ├─ consent：按人、字段、用途和有效期检查授权
  ├─ result composer：只把已确认内容放入整理结果模板
  └─ safety policy：高风险时强制旁路共同分析
  ↓
repository 接口
  ├─ LocalStorageRepository（唯一默认适配器）
  ├─ schema migration / validation / export / import / delete
  └─ 无网络客户端、无第三方分析、无远端 AI 调用
```

页面不直接拼接/修改持久化 JSON；通过领域服务与 repository 操作。文本渲染一律按纯文本转义，不支持用户输入 HTML。原型阶段可以纯 HTML/CSS 链接演示；后续实现可采用 TypeScript + React/Vite 或同仓库适配框架，领域规则保持与 UI 解耦。

## 5. 数据边界与存储建议

### 5.1 实体

- `PersonProfile`：随机本地 ID、语言、同意版本、构念观察、用户修正、创建/更新时间。
- `Claim`：`claim_type`、`speaker_id`、原文/摘要、来源、情境、时间、证据引用、确认状态、未知/不确定描述、共享范围。
- `Relationship`：参与者别名、两方各自授权、双方确认的共同信息、共同约定；不得直接持有对方未授权私密档案。
- `Event`：状态、模式、参与者许可、事实/争议/解释/感受/需求/请求、假设、方案、安全状态、跟进记录。
- `ConsentGrant`：授权人、接收者、字段/claim 清单、用途、版本、时间、撤回状态；授权记录不代表系统可以推断授权之外的信息。
- `Agreement`：双方确认的具体行为、责任、边界、复盘日期、当前状态、来源事件。

### 5.2 localStorage

建议用带命名空间的键：`hwvcm:v1:meta`、`hwvcm:v1:person:<id>`、`hwvcm:v1:relationship:<id>`、`hwvcm:v1:event:<id>`。每个对象有 `schemaVersion`，读取时校验并迁移；写入失败（如容量不足）要保留屏幕内草稿并提示，不能静默丢失。避免把原始叙述复制到日志、控制台或错误信息。

正式产品中，导出为带 `format`、`schemaVersion`、`exportedAt` 的完整 JSON；导入前先解析、校验版本、预览会新增/覆盖的对象并要求确认。删除提供“清除单个对象”和“删除全部本应用数据”，执行后核验 namespace 已清空并离开含敏感内容的页面。导出文件不受浏览器删除控制。当前静态原型中的导入、导出和删除仅为界面示意，不执行操作。双人授权包启用前必须完成口令派生、AES-GCM 加密、密钥与文件分渠道交接和解密预览设计。

### 5.3 本地双人参与的能力边界

纯前端本机应用没有身份认证或可信的远程撤回通道，因此当前 1.1 单人原型应禁用双人授权和共享包入口。未来双人试点必须先实现：每位参与者在各自设备上独立确认、逐字段预览、AES-GCM 加密授权包、分享文件与密钥分渠道交接、接收方解密预览；本机界面不能证明某一输入确由指定身份本人完成。即使完成上述流程，撤回也只能阻止当前工作区继续使用授权，不能删除接收方已下载/复制的副本。未实现身份校验与加密前，不得把静态勾选框描述成有效授权，也不得开放双人共享。

## 6. 事件分析状态机与整理结果策略

状态以规格书为准：

`CONSENT → SAFETY_CHECK → PRIVATE_INTAKE → FACT_MAP → HYPOTHESES → INDIVIDUAL_CONFIRMATION → OPTIONS → MUTUAL_AGREEMENT → FOLLOW_UP`

状态守卫：

- `CONSENT`：当前版本只允许单人用途；记录本人对具体用途的明确同意。双人模式在身份核验与加密授权包完成前禁用。
- `SAFETY_CHECK`：由用户私密自评是否担心威胁、控制、报复或人身风险；只有用户明确表示目前无相关担忧，才可进入 `PRIVATE_INTAKE`。任何担心、犹豫或不确定都只进入 `SAFETY_SUPPORT`，停止共同输入、假设与和解建议。文本中的风险词最多触发本地的私密确认与支持选项，不得单凭关键词自动判定风险或诊断用户。
- `PRIVATE_INTAKE`：当前版本仅由本人填写；每条内容带 speaker、来源和私密范围。双人分开填写属于后续试点能力。
- `FACT_MAP`：单人版只保留本人可核对的事实、本人叙述和争议/未知内容，不替用户裁决真假；双人共识仅在未来双方分别确认后呈现。
- `HYPOTHESES`：至少呈现两种可修正解释，必须标“待验证假设”，列出各自依据与未知项；不得将缺席方猜测当作其自述。
- `INDIVIDUAL_CONFIRMATION`：当前版本由叙述者逐项保留、修正或拒绝；未完成本人确认前，`OPTIONS` 按钮保持禁用。双人模式启用后，每位参与者仍须在各自设备独立确认并选择共享范围。
- `OPTIONS`：给 2–4 个可选行动，描述责任、边界、成本/外部帮助与复盘时间；不以“和好”作为成功条件。
- `MUTUAL_AGREEMENT`：双人试点阶段只记录双方明确同意的条款；任一方可跳过或结束。当前 1.1 单人原型禁用此状态及共同约定入口。
- `FOLLOW_UP`：询问是否执行、是否感到安全/受压、是否出现新伤害；只有本人再次确认后才回写个人档案。

纯本地 MVP 不集成云端生成式模型。面向用户的“整理结果”由用户输入和可追溯模板组成；未来如要加入本地推理，也需单独审查运行环境、模型来源和敏感信息处理，不改变安全守卫。

## 7. 全局禁则（产品、代码和测试共用）

- 不产生道德分、兼容度/匹配率、关系结果预言、人格定性或谁对谁错裁决。
- 推断只可称为“待验证假设”；显示支撑来源、未知和纠正入口。
- 缺席方动机显示“未知／有待核实”；不得由性别、国籍、文化、政治/宗教等敏感信息默认推断。
- 事实、解释、感受、需求、请求使用不同类型与不同视觉标签，不合并成一个“AI结论”。
- 当前原型禁用共同分享；未来正式授权未经双方分别确认，不得把个人数据带入关系视图或整理结果。
- 高风险分支禁用联席协商流程；安全提示不得鼓励当面对质或要求用户解释给潜在施害者。
- 用户输入作为不可信文本；不注入 HTML、不执行脚本、不自动打开输入中的链接。

## 8. 安全与合规界面要求

- 固定声明：**“研究原型，尚未完成心理测量学验证；仅提供认知与沟通反思辅助，不提供心理诊断、人格裁定或关系结果预测。”** 静态设计稿另固定标注“本原型不保存真实数据”。
- 产品版解释 `localStorage` 的实际含义：不上传到本产品服务器，但不是设备加密；建议使用个人设备、屏幕锁并谨慎导出。静态原型不得声称数据已保存。
- 安全支持页提供退出/清理当前内容和本地求助建议。紧急联系人、热线号码须按首发地区由专业人员核验后配置；未核验地区不能展示猜测的号码或声称全天候服务。
- 宗教、政治、健康等敏感数据遵循目的限制、最小化和单独明确同意；未经许可的量表题目/翻译不得嵌入。
- 上线前应完成人类专家安全评审、法律和量表许可核验、数据删除/导出测试。当前原型不构成合规或临床验证结论。

## 9. 可审查的交互验收点

1. 首页三个场景入口都可进入；空档案下可直接开始事件流程。
2. 每条档案观察可看见来源、时间、确认状态和“不确定/未知”；19 项展示相对次序而非总分。
3. 当前原型双人共享入口明确显示“暂未开放”；正式启用后默认零共享，并须通过独立设备确认、加密包预览与分渠道密钥交接。
4. 单人事件页对缺席方明确显示未知，不生成其画像。
5. SAFETY_CHECK 中任何担心或不确定都只到安全支持；只有本人明确表示目前无相关顾虑才能继续。风险词不单独触发诊断或自动分类。
6. 假设至少两条，均有“待验证”标识及本人逐条保留/修正/拒绝的动作；未完成确认时，整理结果入口不可用。
7. 约定回写需二次明确确认，取消后档案保持不变。
8. 产品版 JSON 导出/导入可理解、可预览；删除单对象与全部数据都有清楚范围提示。静态原型相关控件明确标注为示意且不执行操作。
9. 任何页面都没有匹配率、道德分、关系预测或未授权第三人画像；用户界面统一称“整理结果”，不把内部报告术语暴露为产品承诺。

## 10. 版本边界建议

- **1.1 本地单人研究原型：** 首页、18 题可跳过访谈、19 项相对排序、个人档案/来源标注/JSON、单人事件分析、事实/解释分层、安全分支、关于与数据管理。原型界面不保存真实数据；产品版优先验证“理解整理是否可用”，不引入自动心理推断，双人参与保持禁用。
- **1.2 双人自愿试点：** 只有在身份边界说明、双方独立确认、加密授权包、分渠道密钥交接、接收预览、撤回边界与安全测试完成后，才考虑开放逐项共享、共同差异地图、约定与复盘。
- **验证阶段：** R0–R5 研究门槛通过前不升级科学有效性声明，不以新增构念数量作为产品成功标准。

## 11. 原型文件

- `design/hwv-cm-prototype/`：首页、档案、关系（双人共享未开放）、同意、安全自评、私密输入、事实与假设确认、整理结果、安全支持、复盘、关于与数据管理屏。
- 原型仅用于信息架构和交互审查，不连接存储、不执行推断、不保存真实用户数据。
